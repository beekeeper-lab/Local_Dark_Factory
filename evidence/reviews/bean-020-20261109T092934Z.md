## Defect: every HARD rule that is not same/different-table now refuses the solve

`src/seating_planner/solver/hard.py`, new `for rule in event.rules:` loop: `rule.kind not in (RuleKind.SAME_TABLE, RuleKind.DIFFERENT_TABLE)`. The bean asks only for a hard *adjacent-seat* rule to refuse; the bean text never mentions min_distance. The loop also catches hard `min_distance`, and `default_wedding_rules()` ships `template-accessible_seating`, a group-bound HARD `min_distance` rule (the template's only hard rule). The refusal fires on kind alone, before participants are looked at, so an event started from the template cannot be solved even with an empty accessible_seating group.

Demonstration (pinned gate image, exports of main and PR head, 4 guests, 2 tables, `rules=default_wedding_rules()`, `solve_hard(..., mode="planning")`):

No test covers the default template.

Options for the owner: restrict the refusal to adjacent_seat; refuse only with at least 2 eligible participants; or change the template.
