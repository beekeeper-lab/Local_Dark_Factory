## Defect: the keep-set search assumes "keep nothing" is feasible

`hard.py:862-875`, `keep_probe`: builds its model at real capacities, no slack bound.
The "solos first, mark infeasible-alone items, skip pairs containing a marked item"
rule only works if the empty keep-set (everything removed) is itself feasible — if
it is not, every item fails when kept alone (regardless of whether it is really a
cause) and gets named, since adding anything to an already-infeasible baseline stays
infeasible. Two ordinary situations hit this:

- **A seat shortage the probe's own capacities don't cure** — `keep_probe` never
  applies `slack_bound=shortfall`, so any shortfall makes "keep nothing" infeasible
  before considering rules or locks at all.
- **A frozen low-disruption chart that itself violates capacity** (e.g. three
  guests already charted onto a two-seat table) — movement_limit=0 cannot fix
  this regardless of which rules or locks are kept.

Case A (7 guests, three 2-seat tables, a contradictory rule pair `r-a`/`r-b`, a
harmless rule `r-ok`, a harmless lock on `g5`, 1-seat shortfall):
```
main  planning: rules=('r-a','r-b')          short=1 unlock=[]
head  planning: rules=('r-a','r-b','r-ok')   short=1 unlock=['g5']
head  low_disruption: same bystanders named
guard: drop r-a, +1 seat anywhere, r-ok and the lock both kept -> FEASIBLE
```
Case B (no shortfall, movement limit 0, frozen chart puts 3 guests at a 2-seat
table, a harmless bystander rule and lock elsewhere): main names no rule and no
lock; head names the bystander rule and lock the same way.

At scale: 34 rules + 20 locks + a 1-seat shortfall + one real contradictory pair
names ALL 34 rules and ALL 20 locks.

**Random check** (600 generated events, both modes, every named item checked
against a brute-force conflict oracle): head names a non-cause in 94 of 447
infeasible events (84 of those have a shortfall) against 8 on main; head's named
set fails to actually cure the event in 22 cases against 92 on main — head is
still far better at sufficiency, but over-naming is back.

**Suggested fix** (checked, not committed as a verified patch): give `keep_probe`
the same `slack_bound=shortfall` the removal probe already uses, and skip the
whole keep-set phase when `keep_probe(frozenset(), frozenset())` is itself
infeasible. With that: cases A and B are correct, `tests/solver` passes (66), and
the 600-event over-naming count drops to 16 (all still carrying a shortfall,
unverified further).
