**The four focus points:**
1. **The core never imports tkinter, and the tests prove it.** `game.py`, `strategy.py`, `session.py` and `__init__.py` have no tkinter import. Leak mutants were run against `test_gui_isolation.py` in the gate image:
   - `import tkinter` in session, `from tkinter import messagebox` in game, `import tictactoe.app` in `__init__` and `__import__("tkinter")` in session: each is a collection error, so the gate fails.
   - A guarded `try: import tkinter / except ImportError` in strategy: `1 failed, 2 passed`. The `ast` test catches it.
   - The only escape is a guarded `importlib.import_module("tkinter")` (`3 passed`). It would be caught on a machine that has Tk (the subprocess asserts `'tkinter' not in sys.modules`), and in the gate image it cannot load Tk anyway. Minor.
2. **The window re-reads `session.board` after `new_game()`.** There is no real Tk or Xvfb on this host or in any local image, so a probe of five images got `libtk8.6.so` missing or no tkinter. I drove the window headlessly with a fake `tkinter` package (`scratchpad/faketk/`) instead. It records `bind` handlers and fires clicks through them the way Tk's `CallWrapper` does: an exception goes to `report_callback_exception` and the loop continues. The oracle (`scratchpad/oracle.py`) walks every human click sequence and checks three things:
   - after every event, the label texts equal `session.board.cells` and the status equals `session.message` or the live text
   - New Game at every state empties all nine labels, replaces the `Board` object, and lets the next click place X with an O reply
   - every click on an occupied cell or a finished board leaves everything unchanged

   Result: `{'states': 776, 'clicks': 775, 'occupied': 1808, 'post_end': 4401, 'new_game': 776, 'errors': 0}`. The endings were 350 "You lost. Better luck next time.", 127 "It's a draw." and 12 "You win. Congratulations.", which matches bean-003 and bean-004 exactly.
3. **A click on an occupied live cell is caught.** `app.py:50-53` catches the session's `ValueError`, nothing changes and the window repaints. The oracle ran 1808 such clicks with no callback error reported. Even uncaught, real Tk would print a traceback and keep the mainloop running; it would not crash. The suite pins this: removing the `try` fails 1 test.
4. **The README does not work as written.** See the defect above. The entry point itself is fine. `runpy` of `tictactoe` with the fake tkinter builds one root titled "Tic-Tac-Toe" with the status label on row 0, the cells on rows 1-3 and New Game on row 4, then enters `mainloop`.

**Risks for the owner's manual check (ac3–ac5), undemonstrated (no display here):**
