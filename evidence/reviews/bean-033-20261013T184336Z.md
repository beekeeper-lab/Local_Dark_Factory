## Defect: a plain seat shortage gets blamed on the movement limit

`hard.py:730-736`, `_diagnose_low_disruption`'s limit-lift probe — pre-existing code
this bean's background says is "untouched" — now builds its model with
`slack_bound=shortfall`. That probe exists to answer one question: does removing
the movement limit ALONE, at the event's real capacities, restore feasibility? Once
it's given the shortfall's extra seats too, any plain shortage trivially passes it,
so the report claims "the cause is the movement limit, not capacity" and omits
`add_capacity` entirely — even when the limit is generous (100) and raising it to
the sky would still leave the event short a seat.

```
# the hidden ac5 fixture itself, re-run in low_disruption (movement_limit=100)
main:  recs = [add_capacity, add_table]
head:  recs = [raise_movement_limit]   <- wrong; the limit was never the cause
       "...moving at most 100 guests...; the cause is the movement limit, not capacity"
```
The hidden tests don't catch this because ac5's test only asserts no lock is
named in low-disruption mode; it never checks which recommendation kind comes back.

A 600-event random fuzz check (locks + rules + shortages, both modes) found head
omits `add_capacity` despite a counted shortfall in 51 of 600 events (0 on main),
and names `raise_movement_limit` when the limit is in no real conflict in 32 of 600
(0 on main).

**Fix direction (not yet implemented or verified as a patch):** drop
`slack_bound=shortfall` from this specific probe, restoring real capacities as
main's equivalent check used — the limit-lift question and the shortage question
are independent, the same principle ac5 already applies to locks and rules.
