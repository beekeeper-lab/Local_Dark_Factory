## ac12 is built correctly; run 7's defect is fixed

carrying `shortage_only: bool` alongside `named_rules`/`named_locks`
(`hard.py:886-900`), set `True` only when the pass's own shortage-alone short-circuit
(`hard.py:966-967`) fires, and `False` on every other return path — including the "every

the flag exists to distinguish from a matched short-circuit. `_diagnose_low_disruption`
(`hard.py:728-804`) now checks `first.shortage_only` as well as `first.named_rules`/

`second.shortage_only` into whether pass 2 "found something" for the purpose of setting

treated the same as a named cause, never conflated with "found nothing."

## Both of this round's test corrections are mathematically sound

**The packed-event fixture (ac9/ac11, `_packed_event`, `hard.py` test file line ~403):**
locks are 5 guests to `t-01` (capacity 5), exactly at capacity, not 6 as run 7's version
had it. Traced every keep-set probe `_pooled_search` actually runs at `time_limit_s=0.2`
against this fixture (67 keep-set calls): 5 hit `undecided` at exactly ~0.200s (all
involving the packed lock block), the rest resolve in ~0.10-0.20s. The timeout the test
exists to exercise is real and reliably reproduced, not a coincidence of the particular
run — confirmed stable across 3 repeated full-suite runs.

**`test_named_causes_are_real_and_enough` (fixture a):** verified independently via direct
`solve_event` calls that more than one minimal fix exists — `{r-a, r-diff}` (drop both,
keep both locks) cures it, and so does `{r-same, release(g-2)}`, and so does
`{r-diff, release(g-2)}` and `{r-diff, release(g-3)}` — while `{r-a, r-same}` does not.
Running the actual diagnosis against this fixture names all three rules and both locks
(the union of several overlapping proven keep-sets, consistent with the bean's own
non-goal "no guarantee the named set is the smallest"); the test's necessity/sufficiency
guards (not a hardcoded exact set) all pass against this real output.

**`test_locks_are_named_as_locks` (scenario b):** the actual diagnosis names *both*
`r-same` and `r-diff` (not "never both" as the comment speculates) plus all 6 locks in the
packed block; the test's own assertions (`named_rules_b & {...}`, `named_rules_b <= {...}`)
accept this, and the sufficiency guard (drop named rules, release named locks) passes.
The prose comment overclaims slightly ("never both or neither") but the assertions
themselves are correct and not weakened to hide anything — a wording nit, not a logic bug
(noted below under Minor).

Both corrections are genuine fixes to fixtures that admit more than one right answer, not
hidden regressions.
