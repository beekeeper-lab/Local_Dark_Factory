## Defect: curing the shortfall is checked against one placement of the extra seats

`hard.py:761-766` splits the shortfall round-robin across tables
(`base, extra = divmod(shortfall, len(event.tables))`) before asking whether the event
is solvable at all with every rule kept. That commits to one placement before asking
whether a placement exists: a same-table group that only fits once a *specific* table
gains room can be told the shortage does not explain it, and the group's own rule is
blamed instead.

Tables of 3 and 1 seats, 5 guests, rule A (3 guests, same table) and rule B (2 guests,
same table), one seat short:

```
podman run --rm --network=none --userns=keep-id -v $S/{main,head}:/work:Z,ro \
  -v $S/demo2.py:/demo.py:Z,ro -e PYTHONPATH=/work/src -w /work \
  ghcr.io/beekeeper-lab/factory-gate-python:20260914 python /demo.py spread
main: infeasible, rules=(), shortfall=1, [add_capacity, add_table]
head: infeasible, rules=('A','B'), shortfall=1, [... change_hard_rule x2]
keep ALL rules, +1 seat at t2 (not t1): feasible
drop A and B, no extra seat: still infeasible
```

One more seat at t2 (not t1, where the round-robin split put it) solves the event with
both rules kept, so neither rule may be named — main gets this right, the head does not.
Breaks ac5 and ac3. A second case (`spread_one`, a single 3-guest group across three
1-1-2-seat tables) showed the same pattern.

**Fix, verified by the operator session:** every table gets the full shortfall as slack
(not a split share, not all of it on one table) when checking whether curing the
shortage alone restores feasibility — no single table can ever need more than the whole
shortfall to absorb one real placement of it. Checked against `spread`, `spread_one`,
`mixed` (shortage + real conflict + harmless rule), `short2` (a 2-seat shortfall), the
full 60-test solver suite, the three hidden tests (one new, from ac6), and performance
(no measurable cost: 22 rules with a shortage, 0.04s). Landed as bean-032's ac6
(Local_Dark_Factory PR #91).
