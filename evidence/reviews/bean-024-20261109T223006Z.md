## Demonstrated defect: the worker-count pin only covers planning

`tests/solver/test_worker_count.py`, `test_requested_workers_are_used`: the spy that reads the worker count each solve actually ran with is only exercised in planning mode; the low_disruption and event_day cases in `test_every_path_records_the_request` check only the recorded field. Demonstration: changing `hard.py` `outcome = run(built, cfg)` to `run(built, replace(cfg, num_workers=1) if mode != PLANNING else cfg)` still records the request and both tests pass (`2 passed in 0.22s`). The bean intent says "applied to every CP-SAT solve it runs" and names those paths: this is the original defect restricted to two modes, and the pin misses it.

Fix: run the spy over all three modes with N above 1, and add an infeasible low_disruption and event_day case that checks the recorded count.
