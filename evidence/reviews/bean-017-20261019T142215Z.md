## VERDICT: do-not-merge

## Defect (demonstrated)

`GuestImport.apply()` can crash with an **uncaught `ValueError`** instead of either succeeding or raising the documented `CsvImportError` refusal — on a file that `preview_import()` reports as entirely clean (no invalid/missing rows). This directly breaks ac4 ("applying creates/updates exactly the counts the preview reported") and the apply-side safety the bean's intent describes.

**Cause** (`src/seating_planner/importer/guest_import.py:256-271`, `_apply_actions`): for a create row with no `id`, the generated `imported-N` id is checked only against `{g.id for g in event.guests}` *at the moment that row is processed* — it does not reserve against ids that a **later** row in the same CSV will use explicitly. If an earlier no-id row is assigned `imported-1` and a later row in the same file carries the literal id `imported-1` (which does not match any existing guest, so `_plan` classifies it as a plain create, not a duplicate-id-in-file collision — that check only fires when the same literal id appears twice), the second `event.add_guest(...)` call raises `ValueError: event 'e1': duplicate guest id 'imported-1'` from `Event._check_unique_ids`, uncaught.

**Repro** (run in the pinned gate image `ghcr.io/beekeeper-lab/factory-gate-python:20260914`, exported branch tree via `git archive`):

```
$ podman run --rm --network none -v "$PWD":/work:Z -w /work ghcr.io/beekeeper-lab/factory-gate-python:20260914 python repro_imported_id_collision.py
```
CSV: header + `,Alice First,confirmed,,` then `imported-1,Bob Second,confirmed,,` against an event with 0 guests.

Output:
```
PREVIEW: Preview(invalid=(), missing=(), duplicates=(), would_create=2, would_update=0, ...)
preview says would_create=2, would_update=0
Preview reports nothing wrong with this file. Now calling apply()...

APPLY CRASHED with uncaught ValueError: event 'e1': duplicate guest id 'imported-1'
```

This is a real, if narrow, TOCTOU-shaped gap in the generated-id scheme: it only looks backward (already-applied rows), never forward at the rest of the batch. A CSV containing the literal string `imported-N` as a guest id (plausible if an org re-exports a file that itself came from a prior import) reliably triggers it.
