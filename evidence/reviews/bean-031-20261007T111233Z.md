## Defects

1. **Unlock advice names every stored lock (`hard.py:813`, `:833`).** All eligible
   non-unlocked locks are probed and named together. N1 (ac2's shape plus four locks that
   agree with the chart and one to a roomy table) is told to unlock 8 guests; dropping the
   2 at the overfilled table is enough. A lock that agrees with the chart can never matter
   (the single-lock probe in the same file already says so). ac2 asks for the locks "at
   that table".
2. **Mixed causes are advised without a probe (`hard.py:875-900`).** When neither the
   unlock probe nor the capacity probe succeeds alone, both causes are named unchecked.
   N2: following only the unlocks, or only the capacity, leaves it infeasible; following
   both is feasible. N3 also asks for capacity at t-3 that is not needed, with false
   wording ("pinned to hold 2 guests"), because a contradicting lock is counted at both
   tables. Partly an acceptance-criterion gap: ac5 asks each kind to work on its own,
   which no split by kind can meet for mixed shapes.
