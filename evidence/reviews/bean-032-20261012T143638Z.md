## Defect 1 (blocking): a plain seat shortage names every harmless rule as a conflict

`hard.py:764` builds the rule-removal probe base with every table enlarged to hold all
eligible guests (`max(t.capacity, len(eligible))`), to separate "is this a shortage" from
"is this a rule conflict". But rule probes are then run on that same artificially slack
model: with every table able to seat everyone, removing *any* rule trivially succeeds,
so a rule that conflicts with nothing is named anyway.

5 guests, two 2-seat tables, one harmless rule (`r-ok`, same-table on two guests who are
never near capacity):

```
== main            planning: infeasible, rules=(), shortfall=1, [add_capacity, add_table]
                   dropping r-ok with no extra seat: still infeasible (correctly unrelated)
== head (bean-032) planning: infeasible, rules=('r-ok',), shortfall=1, [... change_hard_rule]
```

Breaks ac3 ("names no rule that is not part of some conflict") and the bean's own
background claim that a plain shortage "is already reported correctly today" — it no
longer is. The new tests miss it because their own ac3 check uses the same inflated
capacity model the code uses (`test_complete_diagnosis.py:301`, `_hold_all`), so the
test and the bug share the same blind spot.

## Defect 2 (scope gap, not a regression): the subset search stops at pairs

`hard.py:784-785` tries single removals, then every pair, then stops. Three independent
contradictions (each needing its own rule removed) name nothing on both main and the
head — not a regression, since main never handled this either, but a case the bean's own
background describes ("whenever two things are wrong at once... whenever two **or more**
are wrong"). ac1 only requires the two-conflict case, which does pass.
