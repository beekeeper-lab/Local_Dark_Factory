## 1. The fix, as shipped

`preflight.py` adds `_effective_guests(rule, groups)`, which returns `frozenset(rule.guests)` when non-empty, else expands `rule.group_id` through a `{id: Group}` map, else `frozenset()`. `_contradictions` builds `groups = {g.id: g for g in event.groups}` and now calls `_shared_pair(_effective_guests(same, groups), _effective_guests(diff, groups))` instead of reading `.guests` directly. `_shared_pair`'s own logic (smaller-set-must-be-exactly-2-and-a-subset-of-the-larger) is unchanged. A new test, `test_contradictory_hard_rules_through_a_group`, pins the round-1 repro.

## 2. Item 1 — round-1's exact repro, reproduced independently

Built the same shape fresh (not reusing the fixed test file) — a 2-member group `grpA={g1,g2}` with a hard `SAME_TABLE` rule bound via `group_id`, plus a hard `DIFFERENT_TABLE` rule naming `g1`,`g2` explicitly:

```
run_preflight(event) == [Finding(kind='contradictory_hard_rules',
  message='hard rule r-together keeps g1 and g2 at the same table, but hard rule r-apart requires them at different tables',
  rule_ids=('r-together', 'r-apart'))]
```

Exactly one finding, naming both rules. Round 1's gap is closed.

## 3. Item 2 — adjacent shapes

**Both rules group-scoped, groups overlap in exactly 2 members (new shape, not round 1's repro):** `grpA={g1,g2,g3}` hard `SAME_TABLE` via `group_id`; `grpB={g2,g3,g4}` hard `DIFFERENT_TABLE` via `group_id`. `g2`/`g3` are forced together by A and apart by B — structurally the same class of contradiction as round 1's, just with both sides group-mediated and both groups larger than 2. **Result: `[]` — not flagged.** Root cause: `_shared_pair` still requires the *smaller* of the two effective-guest sets to have exactly 2 members and be a subset of the larger; it never computes a general intersection. Here both sets have 3 members each, so `len(small) != 2` short-circuits before any overlap is checked, regardless of what the intersection actually is.

I'm not calling this a blocking defect. ac1's text is explicitly scoped to "the same guest pair," and the bean's own non-goal says "no attempt to prove general infeasibility (that is the solver's job)." Round 1's defect was a direct instance of that AC silently failing (a group *of two* **is** a guest pair, just referenced indirectly). This new shape requires computing the intersection of two independently-sized group memberships to find a sub-pair — a step further into general inference than "the same guest pair" describes, and consistent with checks staying "structural only, never a search." It is, however, the same root cause family (group-mediated hard rules under-resolved) and a plausible candidate for a follow-up bean or an explicit non-goal note; flagging for the operator's awareness, not as a merge blocker.

**3-member group, same_table and different_table hard rules both scoped to the same whole group (`grpC={g1,g2,g3}` on both sides):** `run_preflight(event) == []` — correctly not flagged. This matches round 1's own framing: the `len(small) != 2` guard is a deliberate scope boundary (no "partial group" concept exists), not a new requirement introduced by the fix.

**Control check — 3-member group vs. an explicit pair fully contained in it** (`grpC={g1,g2,g3}` hard `SAME_TABLE`, explicit hard `DIFFERENT_TABLE` on `(g1,g2)`): correctly flagged, one finding, `rule_ids=('r-same-C','r-diff-explicit')`. Confirms the `len(small)==2`-and-subset path still works correctly whenever one side genuinely reduces to a pair, including when the other side is a larger group — this is the path round 1's fix actually needed to unlock, and it works.
