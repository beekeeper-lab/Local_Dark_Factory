FORGE build line · Fedora Server, headless, SSH-only

The Dark Factory A lights-out software line: the judge reviews an immutable candidate commit, deterministic policy classifies it, and only proven low-risk tiers ever ship without a human.

You define intent and judge output. Between those ends the line decomposes, codes, checks, and reviews on its own. This version closes the review-binding gap (the judge now reviews a real commit SHA), ships the contracts as machine-readable artifacts (JSON Schemas + a checkable implementation plan), restores the full sandbox contract, and specifies the serial model lifecycle that Q8 residency makes likely.

v4.0 · 2026-09-13 · owner: Forge factory · status: candidate for baseline approval (awaiting human owner sign-off) · companions: DARK_FACTORY_IMPLEMENTATION_PLAN.md, schemas/*.json · changelog & references in §12

Three standing rules.

1. No auto-merge to start. The line opens PRs; a human merges. Auto-merge unlocks per risk tier only on numeric evidence (§06, §10).

2. A model never sets its own authority. The controller computes the binding risk tier and effective write-paths from deterministic policy on the actual diff; the judge may raise a tier, never lower it (§06).

3. The judge reviews an immutable candidate commit — not an uncommitted diff — and that exact SHA is what gets pushed and merged (§05, §07).

01 — AUTHORITY

Models propose; policy classifies; the controller decides — over a real commit

The worker can edit anything in its worktree and the judge can misread a task, so neither may hold authority over its own blast radius, and neither may be reviewed in a form that can still change afterward. The judge is not the sole source of the risk tier, the effective write-paths, or the acceptance fixtures — and it reviews an immutable candidate commit, whose SHA is recorded in the verdict and is exactly what gets pushed and merged.

judge · architect

Proposes beans, a suggested tier, and a suggested human-review flag; reviews base..candidate. All advisory — the controller can only be raised by them, never lowered.

worker

Qwen3.8-27B via Pi in a locked sandbox with no git binary and no credentials. Proposes edits only inside allowed paths.

controller

Deterministic Python. Computes the binding tier and effective paths, gates, creates the candidate commit, owns all git and every merge decision, stamps provenance.

Phase 0 — measure through Ollama, at real context sizes

Ollama’s default context is 4096 tokens, so a naïve run measures 4K. Set the context explicitly per run, and don’t launch a second ollama serve if Ollama already runs under systemd (it will fail with address already in use) — reconfigure the service or use a separate port for benchmarking.

# Permanent config on Forge (Ollama already under systemd):
sudo systemctl edit ollama.service      # add to [Service]:
  # Environment="OLLAMA_KEEP_ALIVE=-1"
  # Environment="OLLAMA_MAX_LOADED_MODELS=2"
  # Environment="OLLAMA_NUM_PARALLEL=1"
sudo systemctl restart ollama.service

# Benchmark each context size explicitly (memory ≈ parallelism × context):
for ctx in 16384 32768 49152; do
  OLLAMA_CONTEXT_LENGTH=$ctx  # set via systemd override or the benchmarking instance
  # preload both, then read actual residency + GPU/CPU split:
  ollama run gpt-oss:120b "" ; ollama run qwen3.8:27b-q8_0 "" ; ollama ps
done
  • Record residency and the GPU/CPU split from ollama ps at 16K / 32K / 48K.
  • Measure prompt-processing and generation speed separately.
  • If both won’t co-reside: time an actual model switch (this feeds the serial lifecycle in §07).
  • Run the gpt-oss Harmony conformance test before trusting a verdict (references in §12).

Record every figure with model digest, quant, backend version, and context length. Until then, treat the numbers above as hypotheses.

04 — BEANS

A bean must be able to satisfy its own definition of done

If the DoD requires tests, the test paths must be writable; the risk_tier and allowed_write_paths are proposals the controller intersects with policy. Validated against schemas/bean.schema.json.

id: bean-014
title: Add idempotency keys to the payments POST endpoint
intent: Prevent duplicate charges when a client retries POST /payments.
context: { read_paths: [ src/api/payments.py, src/db/models.py, src/util/idem.py ] }
allowed_write_paths:                 # PROPOSAL — controller intersects with repo policy
  - src/api/payments.py
  - src/db/migrations/**
  - tests/api/test_payments.py       # DoD requires tests → tests must be writable
acceptance_criteria:
  - id: ac1  Repeated Idempotency-Key → one row; both responses match.
  - id: ac2  Keys expire after 24h.
constraints: [ no new deps, p95 < 150ms, migrations reversible ]
suggested_risk_tier: 2               # advisory; controller computes the binding tier
definition_of_done: [ ac met, tests added & green, mypy clean, migration reversible ]
non_goals: [ do not touch the refunds path, no client SDK changes ]
dependencies: [ bean-009 ]
invariants_ref: factory/invariants/payments.yaml   # independently reviewed source

Independent validation means human or a different model family

Some acceptance fixtures come from an independently reviewed source (invariants_ref) outside the worker’s reach. For important invariants, independence means a human or a genuinely different model family — a second, differently-prompted instance of the same model is not independent. And a generated batch of beans passes a human/independent spec-audit admission before entering the queue; beans do not self-admit.

05 — THE LOOP

The judge reviews a commit, not a floating diff

  1. Decompose & admit. judge → spec-audit → queue Beans emitted, batch-reviewed, admitted as ready.
  2. Lease & branch. controller Atomically lease the next ready bean whose deps are merged. Cut bean/<id> from up-to-date main; expose only the editable tree to the worker.
  3. Build. worker via Pi RPC, sandboxed Edits only within effective allowed paths. No git, no commit, no credentials.
  4. Contain — reject, don’t strip. controller Any edit outside allowed paths → reject the whole proposal, record offending paths, reset to last clean state, scoped feedback. Repeats quarantine. Enforce max diff/file count; secret scan.
  5. Classify & gate against baseline. controller in podman Compute the binding tier (§06). Run gates + independent invariants + hidden tests vs baseline with integrity checks. Failure → feedback, revision++, step 3.
  6. Create the candidate commit. controller Commit the contained, gated tree as an immutable candidate_sha on the branch (not yet pushed). Record base_sha, candidate_sha, diff_sha256, gate_run_id.
  7. Judge the commit. controller → judge The judge reviews base_sha..candidate_sha plus gate results — not the worker’s justification. The verdict records candidate_sha (§08); the controller schema-validates it.
  8. Revise if needed. controller → worker On verdict != accept, feedback back, revision++, step 3 (a revision produces a new candidate). Cap/budget → step 10.
  9. Push the reviewed commit, CI, propose. controller → remote CI → human Push the exact candidate_sha, open a PR with provenance + verdict, enter the CI protocol (§07). Before any merge, assert verdict.candidate_sha == pr.head_sha and required checks green for that SHA. Human merges unless the tier is a proven auto-merge tier.
  10. Quarantine, don’t stall. controller On cap/budget/violation, mark blocked with reason + provenance, release the lease, continue.

An unexpected PR-head change is a violation, not a re-review trigger

If pr.head_sha ever differs from the reviewed candidate_sha and the change did not come from the controller’s own rebase path, treat it as a policy violation → blocked + alert, not an automatic re-review. Only the controller’s rebase path (§07) may legitimately produce a new candidate, and that path re-gates and re-reviews.

06 — SECURITY

Independent classification, a hard boundary, a real sandbox, numeric unlocks

Controller-computed binding tier

final_tier = max(policy_tier, model_suggested_tier), from schemas/risk-policy.schema.json. A model that under-reads its change cannot down-classify it.

Change touches…Minimum tier
Docs, comments, internal test data0
Small, isolated code within allowed paths1
DB migrations; auth/authz; CI config; dependency manifests & lockfiles2
Agent-control files — AGENTS.md, CLAUDE.md, .pi/, skills, hooks, prompts, project-instruction files3
Secrets, production infrastructure, destructive ops3

Actions: 0 auto-merge after gates once demonstrated; 1 auto-merge after remote CI + policy once demonstrated; 2 human approval; 3 never autonomous.

The trust boundary

  • Gate definitions and invariants live outside the writable tree and run from there.
  • Effective write-paths = bean paths ∩ human-approved repo policy; protected paths escalate.
  • The worker holds no credentials and has no git binary; the controller stages, commits (candidate), signs, pushes, opens the PR.
  • Reject, never silently strip, out-of-scope edits.
  • Validate against baseline: hidden tests + independent invariants + integrity checks.
  • Repository content is untrusted input, delimited as data — never expands paths or verdict authority.

The sandbox contract (restored, enforceable)

  • Read-only filesystem outside the single editable worktree; that tree is the only writable mount.
  • No Docker/Podman socket; no SSH agent forwarding; scrubbed environment; no credentials inside.
  • Dropped Linux capabilities and no-new-privileges; CPU, memory, process, output, and wall-time limits.
  • Network disabled by default; an allow-listed proxy only for tasks that genuinely need package access.
  • “No git” is enforced structurally: the worker image contains no git executable, .git metadata is never mounted into the worker, and the controller keeps the real worktree outside the worker boundary — only the editable tree is exposed.

Auto-merge unlock — numeric, revocable

  • ≥ 100 human-reviewed PRs in that tier; zero known escapes; ≤ 1 substantive human rejection.
  • All controller fault-injection tests passing; no unresolved high-severity audit findings.
  • Auto-suspend on the first critical escape, or two false approvals within any 30 PRs.

“Human rejected” ≠ “false approval”

Every rejection is classified — defect · requirement_miss · security · preference · stale_branch · unrelated_ci — and only defect/requirement-miss/security rejections of an accept verdict count against the unlock threshold.

07 — MECHANICS

Explicit states, a CI protocol, a model lifecycle, and a real stop

The state machine, with the candidate commit and every side effect

ready → leased → building → containing → gating → committing_candidate → judging
      → (accepted | revise→building | blocked)
accepted → pushing → pushed → pr_open → ci_pending
      → (ci_failed→revise | ci_timeout→retry≤N→blocked
         | stale→rebase→gating (new candidate → re-review)
         | merge_conflict→blocked | merge_pending)
merge_pending → merging → merged            # auto-tier (proven)
merge_pending → (human merges) → merged     # default
terminal: merged · blocked · cancelled
  • Every transition carries an idempotency key (bean-id + candidate_sha); startup reconciliation re-derives true state from Forge (branch, PR, checks, head SHA) and resumes or rolls back.
  • Human merge detection: Forge webhook flips merge_pending → merged; poll + reconciliation are fallbacks.
  • Rebase (from stale) produces a new candidate_sha → re-gate → re-review; a rebase conflict → merge_conflict → blocked. An out-of-band head change is a violation (§05), not a rebase.

The serial model lifecycle (likely production path)

If Q8 + gpt-oss can’t co-reside, switching models is on the critical path and must be an explicit contract, not a side effect. OLLAMA_KEEP_ALIVE=-1 is for the Phase-0 residency experiment only; serial production uses controller-driven load/unload.

# inference-manager contract (controller owns it)
ensure_worker_loaded()   # ollama stop <judge> if resident; preload worker; wait ready
worker_healthcheck()     # /api/tags or a 1-token probe; assert model id + ready
... worker turn ...
stop_worker()            # ollama stop qwen3.8:27b-q8_0
ensure_judge_loaded()    # preload gpt-oss:120b; wait ready
judge_healthcheck()
model_load_timeout = 90s      # EST — set from Phase-0 swap measurement
on model_load_failure: retry ≤ 2 → block bean, alert   # never proceed on the wrong model
# record load_seconds per switch → telemetry swap-overhead %

The emergency stop — three verbs

CommandBehaviorRestart
factory pause (SIGINT)Finish in-flight bean; start no new work.Resume pulls next ready.
factory drain (SIGTERM)Finish current model call / gate, then stop.Reconcile resumes the leased bean from its persisted state.
factory stop-now (control socket)Terminate the worker container now; preserve evidence.Reconcile rolls the bean back to last clean state; lease released.

All three are reconciliation-safe mid committing_candidate/pushing/pr_open/merging via idempotency keys.

08 — VERDICT SCHEMA

A real JSON Schema, bound to the reviewed commit

This is the actual contract (companion: schemas/verdict.schema.json), not an example. It binds the verdict to candidate_sha and the run’s digests, uses enums/ranges, requires fields, and forbids extras. The judge supplies suggested_tier and suggested_human_review; the controller stamps the binding effective_risk_tier and the authoritative human-review decision — the judge cannot set its own review requirement.

{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://forge.local/schemas/verdict.schema.json",
  "title": "Verdict", "type": "object", "additionalProperties": false,
  "required": ["schema_version","bean_id","base_sha","candidate_sha","diff_sha256",
               "gate_run_id","gate_manifest_digest","invariants_digest","policy_version",
               "effective_risk_tier","model_digest","prompt_version","criteria","verdict"],
  "properties": {
    "schema_version": {"const": "verdict/1.4.0"},
    "bean_id": {"type":"string","pattern":"^bean-[0-9]+$"},
    "base_sha": {"type":"string","pattern":"^[0-9a-f]{40}$"},
    "candidate_sha": {"type":"string","pattern":"^[0-9a-f]{40}$"},
    "diff_sha256": {"type":"string","pattern":"^[0-9a-f]{64}$"},
    "effective_risk_tier": {"type":"integer","minimum":0,"maximum":3},  // controller-stamped
    "confidence": {"type":"number","minimum":0,"maximum":1},
    "suggested_tier": {"type":"integer","minimum":0,"maximum":3},
    "suggested_human_review": {"type":"boolean"},              // judge advisory only
    "verdict": {"enum": ["accept","revise","block"]}
    // … criteria[], security_findings[], test_integrity{}, gate_manifest_digest,
    //    invariants_digest, policy_version, model_digest, prompt_version, feedback_to_worker
  }
}

Full schema in the companion bundle, alongside bean, event, gate-manifest, and risk-policy schemas — each additionalProperties:false and validated at its boundary.

09 — TELEMETRY

The metrics that gate the unlocks

  • False approval rate (accept → human-rejected as defect/requirement-miss/security). Clears the §06 threshold before a tier unlocks; drives auto-suspend.
  • Rejection taxonomy: defect · requirement_miss · security · preference · stale_branch · unrelated_ci.
  • Escaped defects: issues found after merge — ground truth over everything upstream.
  • Revisions/bean & rework: high → under-specified beans or an undersized worker.
  • Model swap overhead % (from the inference-manager load times) and blocked rate: operational health; swap overhead informs resident-vs-serial.

10 — ROLLOUT

The phases live in a checkable plan, not decorative boxes

The boxes below are a summary; the authoritative, resumable ledger is the companion DARK_FACTORY_IMPLEMENTATION_PLAN.md with real Markdown tasks. Every phase — including 1, 3, and 4 — requires the same closing ritual: all tasks checked → exit criteria machine-verified → audit report generated → findings corrected → audit re-run → an explicit phase-complete marker committed.

Phase 0

Measure on Ollama

Set context explicitly (16K/32K/48K); record residency + swap time; Harmony conformance. Exit + audit & correction per the plan.

Phase 1

One bean, by hand

Candidate-commit review path validated; allowed-path enforcement; schema-valid verdict; independent invariant runs. Exit + audit & correction.

Phase 2

Controller — worker cannot commit

Full loop + fault injection (restart, unauthorized-path reject, duplicate PR, credential exposure, CI failure, stale branch, wrong-model-loaded). Exit + audit & correction.

Phase 3

Lights-out to PRs

Queue/leases/idempotency/provenance/kill-switch/telemetry. Exit: ≥ 48 unattended hours and ≥ 25 completed beans, reconciliation-after-crash pass, all three stop verbs verified. Exit + audit & correction.

Phase 4

Unlock auto-merge by tier, on evidence

Meet §06 numeric thresholds for Tier 0 only; auto-suspend armed; Tiers 2–3 human/never. Exit + audit & correction.
